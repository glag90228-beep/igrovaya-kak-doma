# Калькулятор меню для сайта трапеза18.рф

Страница `kalkulyator.html`, которая встраивается в существующий **статический** сайт
«Трапезы»: берёт его шапку, подвал, шрифты, токены и скрипты — и добавляет конструктор
заказа с полным меню (74 фуршетных + 58 банкетных позиций), сметой и печатью.

Отдельный сервер не нужен: заявка уходит через тот же обработчик форм, что и остальные
формы сайта (`sendForm()` → Cloudflare Worker → бот).

## Сборка

```bash
cd trapeza/site-kalkulyator
node build.js ../../путь/к/сайту ./site-new
```

Скрипт:

1. читает `furshet.html` и вырезает из неё шапку, мобильное меню, блок «Оставить заявку»,
   подвал, модалку 152-ФЗ, стили страниц и скрипты сайта;
2. подставляет меню из `../menu-data.js` и `../menu-data-banket.js` (то же, что и в
   веб-версии и в панели) плюс фотографии из `img/` сайта;
3. кладёт готовую страницу в копию сайта, правит пункт меню «Калькулятор» на всех
   страницах и добавляет запись в `sitemap.xml`.

Меняется меню — пересоберите страницу и перезалейте `kalkulyator.html`.

## Файлы

```
kb-section.html   разметка и стили конструктора (на токенах сайта)
kb-script.html    логика: каталог, состав блюда, смета, печать, заявка
admin.php         панель меню для хостинга с PHP (правит menu.json)
build.js          сборка страницы из файлов сайта
```

## Панель меню (admin.php)

Кладётся в корень сайта, открывается по `/admin.php`. Пароль хранится хэшем
в константе `ADMIN_HASH` (bcrypt, cost 12); менять через `password_hash`.
Сам пароль в репозитории не держим — он передаётся владельцу отдельно.

Умеет: править название/состав/выход/цену/категорию/меню, отмечать «по запросу»,
скрывать позицию с сайта, удалять, добавлять новые блюда, грузить фото в `img/menu/`,
менять транспортные расходы.

Меню хранится в `menu.json` рядом со страницей; калькулятор читает его при загрузке
и, если файла нет, работает на списке, зашитом в страницу.

Важные детали реализации:

- **Сохранение идёт одним JSON-запросом**, а не обычной формой: на 132 позициях
  обычный POST упирается в `max_input_vars` (по умолчанию 1000) и PHP молча
  выбрасывает часть полей — меню теряется. Проверено: через форму сохранялось
  114 позиций из 133.
- Перед записью делается резервная копия в `menu-backup/` (хранятся 20 последних).
- Резкое сокращение списка (более чем вдвое) требует отдельного подтверждения.
- Загрузка фото проверяется через `getimagesize`, а не по расширению.
- В `.htaccess` сайта `*.json` запрещены к отдаче — сборка выводит `menu.json`
  из-под запрета и закрывает `menu-backup/`. После сохранения панель сама проверяет,
  что файл отдаётся, и предупреждает, если нет.

## Цены на витрине

Карточки на `furshet.html` расходились с прайсом. Таблица `PRICE_FIX` в `build.js`
приводит их к прайсу — и в разметке, и в микроразметке Schema.org. Сборка падает,
если хоть одна замена не сработала (значит, разметка сайта изменилась).

## Блок на главной

`BANNER` в `build.js` вставляется в `index.html` сразу под первым экраном.

## Смета отдельной страницей (`smeta.php`)

Перед отправкой заявки калькулятор шлёт в `smeta.php` **данные заказа** (не готовый
HTML — иначе посетитель мог бы разместить на сайте произвольную страницу). PHP
рендерит документ сам, экранируя всё через `htmlspecialchars`, кладёт его в
`smeta/<код>.html` и возвращает ссылку. Ссылка уходит менеджеру в заявке и
показывается клиенту.

Ограничения: не больше 300 позиций и 30 смет в час с адреса, файлы старше 180 дней
удаляются при следующей записи, папка закрыта от индексации (`robots.txt` +
`X-Robots-Tag`).

## Поиск

Запрос нормализуется (`ё → е`, регистр, пунктуация), разбивается на слова и у
каждого отбрасывается окончание (5–8 букв → минус одна, 9+ → минус две). Слова
ищутся по названию, составу и категории в любом порядке. Если в активном меню
ничего не нашлось, а в соседнем есть — показывается кнопка перехода. Без этого
«семга» не находила «сёмгу», а «мясо перепечи» не находило ничего.

## Редиректы

У сайта остались правила от OpenCart, и одно из них — `^menu/?.*$ → /furshet.html`
— перехватывало `menu.json`: меню из панели не доходило до страницы. Сборка
добавляет в начало блока редиректов страховку: если файл или папка существуют
на диске, они отдаются как есть.

## SEO (замечания Яндекс.Вебмастера)

Сборка переписывает `sitemap.xml` и `robots.txt`: адреса в них были кириллицей,
а протокол Sitemap требует ASCII — отсюда «Обнаружены ошибки в файлах Sitemap».
Домен подставляется в punycode (`xn--18-6kcaym8cgr.xn--p1ai`), в карту попадают
все страницы, включая калькулятор; в robots закрыты `admin.php` и `menu-backup/`,
а `menu.json` явно разрешён (иначе его глотал общий `Disallow: /*.json$`).

В `index.html` добавляется микроразметка `FoodEstablishment` с адресом, городом,
телефоном, часами работы и `areaServed` — подспорье для регионального ранжирования.
Сам регион задаётся только в интерфейсе Вебмастера.

## Проверки

```bash
node check-site.js        # страница, каталог, смета, печать, соседние страницы
node check-mobile.js      # 320–768 точек: вёрстка, заявка, печать, панель
node check-admin.js       # панель: вход, правки, фото, резервные копии
node check-smeta.js       # поиск и ссылка на сохранённую смету в заявке
node check-seo.js <папка> # карта сайта, robots, метатеги, разметка организации
ADMIN_PASS=… node check-security.js <папка>
```

Что закрывает `check-security.js`: доступ к панели и загрузке фото без входа,
перебор пароля без cookie, CSRF на сохранении, экранирование данных заказа
в сохранённой смете, непредсказуемость её адреса, подмену заголовка Host,
ограничение частоты, правила `.htaccess` и `robots.txt`, отсутствие токенов
и паролей в выкладываемых файлах.

Найденное и исправленное по ходу аудита:

- счётчик неудачных входов жил в сессии — хватало удалить cookie, чтобы
  продолжить перебор; теперь он на диске и привязан к адресу;
- имя файла сметы состояло из трёх случайных байт — за сутки перебираемо,
  а внутри имя и телефон клиента; стало восемь байт;
- ссылка на смету собиралась из заголовка `Host` — подменив его, можно было
  увести менеджера на чужой домен; сервер отдаёт относительный адрес,
  абсолютный собирает браузер;
- путь к фото допускал `..`; папка загруженных фото теперь ещё и запрещает
  выполнение кода;
- добавлен общий потолок на количество сохранённых смет.

## Печать

`@page { margin: 0 }` убирает колонтитулы браузера, а на лист попадает только смета —
шапка сайта, каталог, панель итога и формы скрыты.

берутся из `img/` самого сайта. Новые фото: положить файл в `img/` и добавить строку в карту.
